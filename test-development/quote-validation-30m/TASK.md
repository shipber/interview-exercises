# 测试开发现场实操：报价金额是否可信

版本：Q-ON-30 v1.0 · 时长：30 分钟 · 可使用 AI 和公开文档

你接手一个报价接口的发布验证。请根据以下规则编写并运行检查，向在旁的面试官说明结果是否可信、发现了什么、还有哪些未验证。

这是专门为面试制作的合成业务，以下规则是本题唯一依据，不要求物流行业经验，也不代表真实 Shipber 生产规则。环境由面试官提前启动，安装和环境排障不计入作答时间。

## 业务规则

一次报价只处理 USD。`fees` 为 1–20 个独立费用项，`code` 非空且不重复。

每个费用项有公布价 `public_amount`、成本价 `cost_amount`、折扣百分比 `discount_percent`。**折扣 20 表示减免 20%，即支付公布价的 80%。**

1. 单项金额 = `max(公布价 × (1 − 折扣百分比 / 100), 成本价)`，然后按十进制四舍五入保留两位小数，恰好一半时向上取整（ROUND_HALF_UP）。
2. 每个输入费用项都要在结果中保留，按输入顺序返回其 `code` 和金额，包括金额为 `0.00` 的费用项。
3. `subtotal` 是各项已保留两位小数的金额之和。
4. `fuel` = `subtotal × fuel_rate`，再按相同规则保留两位小数。燃油费不再加一次成本托底。
5. `total` = `subtotal + fuel`。所有输出金额均为两位小数的字符串。
6. 输入金额是非负、最多两位小数的十进制字符串；折扣是 0–100 的十进制字符串；`fuel_rate` 是 0–1 的十进制字符串。缺失、`null`、越界等无效业务输入返回 HTTP 422 和 `code=INVALID_INPUT`。本题只需使用普通金额，不考超大数、网络攻击或服务并发。

## 接口与环境

- `GET http://127.0.0.1:8765/health`：环境检查，不代表业务计算正确。
- `POST http://127.0.0.1:8765/quote`：请求见 `example.json`，使用 `Content-Type: application/json`，无鉴权和外部依赖。有效输入返回 HTTP 200。
- 样例的正确金额：BASE `8.00`、HANDLING `4.00`、subtotal `12.00`、fuel `1.20`、total `13.20`。
- 可用任意熟悉的语言编写检查；提供 Python 3.10+ 标准库服务，仅用于启动环境，不考 Python 框架。可以阅读服务源码，**测试预期以业务规则为准**。

面试官已启动服务时，可这样调用：

```sh
curl -s -H 'Content-Type: application/json' --data-binary @example.json http://127.0.0.1:8765/quote
```

本地端口不可用时，使用同一实现的命令行入口；它输出 `status` 和 `body`，本题不要求评估命令行进程退出码：

```sh
python3 quote_service.py --quote-file example.json
```

## 你需要完成的任务

编写一个可重复运行的检查脚本或测试文件：

- 覆盖一个正常场景，以及至少两个你认为重要的边界／异常场景。无需穷举，说明选择原因即可。
- 明确每个场景的预期结果及依据，实际调用接口或命令行入口并判断结果。至少检查金额及必要的业务字段，不仅检查状态码。
- 输出能定位问题的场景名、预期、实际与差异。可以使用手工核算的固定预期值，不必实现完整计价引擎。
- 用实际运行结果说明已证实的问题、业务影响、未覆盖的风险和发布建议。

交付运行命令、代码与输出即可；不要求 PPT、长文档、测试平台或修复服务源码。测试失败并准确揭示业务问题是有效成果。请保留首次运行结果及后续更改依据。
