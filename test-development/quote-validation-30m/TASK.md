# 现场实操：给一个计价程序写自动化测试

版本：Q-ON-30 v1.1 · 30 分钟 · 允许使用 AI 和公开文档

## 你要做什么

这里有一个已经写好的计价程序：输入价格、成本和折扣，它会返回应收金额。

**请另写一个测试程序，给它输入几组数据，自动比较“按规则应该得到的结果”和“程序实际返回的结果”，报告哪里一致、哪里不一致。**

你负责测试，保持 `quote_service.py` 不变。可以阅读它，但不需要修复它，也不需要重新开发一个计价系统。

完成以下三件事即可：

1. 用提供的正常样例跑通一个自动化检查。
2. 自己再设计两组边界或异常输入，写入检查并运行。说明为什么选它们。
3. 展示测试代码、运行命令和结果，解释至少一个预期值是怎么算出来的。如果发现差异，说明可能影响什么。

可以用熟悉的语言、测试框架，也可以写一个简单脚本。预期值可以提前手算后写在测试里。**测试程序应当自己判断通过或失败；只打印接口结果、只写用例文档，还没有完成本题。**

## 先看一个完整例子

`example.json` 是一组正常输入，包含两个收费项目：

| 收费项目 | 原价 `public_amount` | 成本 `cost_amount` | 减免比例 `discount_percent` |
| --- | --- | --- | --- |
| BASE | 10.00 | 6.00 | 20，即减免 20% |
| HANDLING | 4.00 | 1.00 | 0，即不减免 |

这组输入的燃油费比例 `fuel_rate` 为 `0.10`，即 10%。按本题规则：

- BASE：10.00 × 80% = 8.00，高于成本 6.00，所以收 8.00。
- HANDLING：不减免，收 4.00。
- 小计：8.00 + 4.00 = 12.00。
- 燃油费：12.00 × 10% = 1.20。
- 合计：12.00 + 1.20 = 13.20。

正确返回内容如下，HTTP 状态码为 200：

```json
{
  "currency": "USD",
  "fees": [
    {"code": "BASE", "amount": "8.00"},
    {"code": "HANDLING", "amount": "4.00"}
  ],
  "subtotal": "12.00",
  "fuel": "1.20",
  "total": "13.20"
}
```

你的第一个检查可以使用这组输入，比较返回的收费项目及金额、小计、燃油费和合计。结果展示形式不限，例如：

```text
正常报价：PASS
  total 预期 13.20，实际 13.20
  费用明细、小计和燃油费也与预期一致
```

这个例子展示了如何完成一次检查。接下来，由你选择另外两组数据，先确定预期，再让程序运行并比较。预期结果依据下面的规则，不直接复制程序的实际输出。

## 计算规则：以这里为准

这是合成的面试业务，不需要物流知识。“原价”对应字段 `public_amount`。

**每个收费项目单独计算：**

1. 先计算减免后的价格：原价 ×（1 − 减免比例 / 100）。`20` 表示减免 20%，不是收原价的 20%。
2. 将减免后的价格与成本比较，取较大的数。
3. 将该金额按十进制四舍五入保留两位小数，恰好一半时向上取整（ROUND_HALF_UP）。
4. 输入的每个收费项目都应在返回的 `fees` 中保留，`code` 和顺序不变，金额为 `0.00` 的项目也保留。

**然后计算整次报价：**

- `subtotal`：把每个项目已保留两位小数的金额相加。
- `fuel`：小计 × 燃油费比例，再按相同方式四舍五入到两位小数。燃油费无需与成本比较。
- `total`：小计 + 燃油费。
- 金额均以两位小数的字符串返回，例如 `"8.00"`。

**输入要求：**

- `currency` 固定为 `"USD"`；`fees` 包含 1–20 个项目，每项 `code` 非空且不重复。
- 原价和成本是非负、最多两位小数的十进制字符串，例如 `"10.00"`。
- 减免比例是 0–100 的十进制字符串；燃油费比例是 0–1 的十进制字符串。
- 缺失、`null`、越界等无效业务输入返回 HTTP 422，且返回内容的 `code` 为 `"INVALID_INPUT"`。

只需测试你选中的场景，不要求覆盖所有规则。不考超大数、网络攻击或并发。

## 如何调用程序

环境由面试官提前准备，安装和环境排障不占作答时间。你只需调用已启动的接口：

```text
POST http://127.0.0.1:8765/quote
Content-Type: application/json
请求内容：参考 example.json，无需鉴权
```

在本题目录中可先手动试一次：

```sh
curl -s -H 'Content-Type: application/json' --data-binary @example.json http://127.0.0.1:8765/quote
```

随后把调用和比较过程写进你的测试程序。可以复制 `example.json` 后修改数据，也可以在测试代码中构造请求。

若本地接口不可用，面试官会协助处理，或让你使用等价的命令行入口：

```sh
python3 quote_service.py --quote-file example.json
```

命令行输出包含 `status` 和 `body`，分别对应接口状态码与返回内容。用此方式完成自动化检查同样有效，不要求检查命令行退出码。

## 最后如何展示

运行你的测试，向面试官展示：

- 测了哪三组输入，为什么选择它们。
- 每组预期是什么，实际是什么，检查通过还是失败。失败时能看到具体字段的差异。
- 选一个关键预期值说明计算过程；如发现问题，说明是否建议发布及理由。

发现业务问题而让测试失败，是有效成果；不要求让所有检查通过，也不要求写长报告。没完成的部分可以直接说明。

前 5 分钟阅读和确认任务，随后 15 分钟编写并运行测试。第 20 分钟面试官会提供一组新输入，请你说明预期并复用或扩展检查；最后 4 分钟展示和交流。

可以使用 AI 生成或修改测试，但请亲自运行并能解释关键代码和预期值。不使用 AI 不影响评价。所有材料均为合成数据；请勿引入真实客户资料、凭据或前雇主代码。按面试官指定的方式提交代码与运行结果。
