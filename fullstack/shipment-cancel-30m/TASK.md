# 全栈研发现场实操：给运单列表加上取消功能

版本：F-ON-30 v1.0 · 30 分钟 · 允许使用 AI 和公开文档

运营人员建错了一张运单，希望在发货前取消它。我们已经提供一个能显示运单的页面，请你完成“取消运单”这个功能，包括页面交互和后端处理。

## 做完后应该是什么样

以页面中的 **S1001** 为例：

1. 它最初是“待发货”，旁边有“取消运单”按钮。
2. 点击后，页面显示正在处理，并暂时禁止再次点击。
3. 后端取消成功后，这一行变成“已取消”，取消按钮消失，页面提示成功。
4. 刷新页面，S1001 仍是“已取消”，其他运单保持原样。

如果请求失败，页面应提示原因，保留原来的运单状态，并允许重试。

## 后端需要遵守的规则

取消请求为 `POST /api/shipments/:id/cancel`，无需请求体。后端根据当前保存的运单状态处理：

| 情况 | 处理结果 | HTTP 状态 | 错误 code |
| --- | --- | --- | --- |
| 待发货 `ready`，如初始的 S1001 | 改为 `cancelled`，返回运单 | 200 | — |
| 已取消 `cancelled`，如 S1003 或重复取消 S1001 | 保持原样，仍返回运单，视为成功 | 200 | — |
| 已发货 `shipped`，如 S1002 | 拒绝取消，保持原样 | 409 | `INVALID_STATUS` |
| 运单不存在，如 S9999 | 返回错误，不改变数据 | 404 | `SHIPMENT_NOT_FOUND` |

成功响应示例：

```json
{"shipment":{"id":"S1001","recipient":"Alex Chen","status":"cancelled"}}
```

失败响应示例：

```json
{"code":"INVALID_STATUS","message":"已发货运单不能取消"}
```

`message` 用能说明原因的文字即可。取消只改变目标运单的 `status`，其余字段和其他运单不变。已有列表接口 `GET /api/shipments` 返回 `{"shipments":[...]}`，可以用它确认保存结果。
